# Power Query Source and Portability Strategy

## Source

The only report source is the named-table Excel workbook `data/kmb_synthetic_operations.xlsx`. It is generated by `scripts/generate_synthetic_data.py` and validated by `scripts/validate_project.py`.

## Required Desktop implementation

- Create a single text parameter: `pSourceFile`.
- Reference the parameter from one configuration query; do not repeat literal file paths in each table query.
- Connect to Excel named tables rather than sheets or ranges.
- Apply explicit types matching `docs/data_dictionary.md`.

The distributed model stores a portable placeholder instead of a machine-specific path. Run `scripts\set_local_source.ps1` after cloning and use `scripts\set_local_source.ps1 -Reset` before committing changes.
- Create visible failures when a required named table or column is absent.
- Preserve a `DataSource` provenance field in facts.
- Keep dimensions and facts as separate, clearly named queries.

## Relocation test

Relative paths are not assumed to be portable. The clean-copy test must change the parameter through Power BI Desktop, refresh successfully, save, close, reopen, and refresh again.

## Source repair rule

Before changing M, TMDL, or a measure to repair a missing field, inspect the actual Excel named table and compare it with the data contract. Never infer source columns from a model error alone.
